# Windows 11 部署教程：从零开始安装与配置

## 前言

Windows 11 延续 Windows 桌面系统的安装流程，同时要求兼容的 64 位处理器、UEFI、安全启动能力和 TPM 2.0。安装前确认硬件与授权条件，比绕过检查后再排查安装或更新问题更稳妥。

本教程介绍从准备安装介质、安装系统到首次启动后检查更新的基本流程，分别指出 VMware 虚拟机与物理机需要注意的地方。文中部分原始安装截图暂缺，现阶段以文字说明和关键选项核对点替代；真实示意图将在后续更新中补足。

!!! info "与 Windows 10 教程的关系"
    如果你已经阅读过 [Windows 10 部署教程](windows-10.md)，安装介质、分区和初始配置的整体思路会很熟悉。本文重点说明 Windows 11 的硬件要求、虚拟 TPM 和 OOBE（首次开机设置）差异。

## Windows 11 版本选择

| 版本 | 适合场景与选择依据 |
| --- | --- |
| **家庭版（Home）** | 个人日常使用；不提供远程桌面主机、Hyper-V 等部分专业管理功能 |
| **专业版（Pro）** | 需要远程桌面主机、Hyper-V、BitLocker 或组织设备管理功能的用户 |
| **专业工作站版（Pro for Workstations）** | 有特定高端硬件和工作负载需求时选择，普通桌面使用通常不需要 |
| **企业版（Enterprise）** | 由组织按批量授权和管理方案部署，不是个人安装时默认升级的选项 |

选择与你的许可证和实际用途匹配的版本。Pro 功能较多，但需要相应授权；安装介质、产品密钥和数字许可证必须对应同一版本，不能因为选择 Pro 就自动获得 Pro 授权。

## 部署前准备

### 硬件要求

安装前应对照 [Microsoft Windows 11 系统要求](https://www.microsoft.com/windows/windows-11-specifications)检查设备。以下为常见最低要求摘要；处理器还必须属于微软支持的兼容型号：

| 项目 | 最低要求 | 实用建议 |
| --- | --- | --- |
| **处理器** | 1 GHz 或更快、至少 2 核的兼容 64 位处理器或 SoC | 先核对微软支持的处理器列表，满足频率和核心数不代表一定兼容 |
| **内存** | 4 GB | 虚拟机建议分配 8 GB 或更多 |
| **存储** | 64 GB 或更大 | 虚拟磁盘建议至少 80 GB，并为更新和应用留出空间 |
| **固件与安全启动** | UEFI，且支持 Secure Boot | 使用 UEFI 启动；优先启用 Secure Boot |
| **TPM** | TPM 2.0 | 实体机检查固件 TPM；虚拟机优先添加 vTPM |
| **显卡** | DirectX 12 兼容，WDDM 2.0 驱动 | 确认设备或虚拟机图形驱动可用 |
| **显示器** | 对角线大于 9 英寸、每色通道 8 位，支持 720p | 低于此规格的显示设备不符合官方最低要求 |
| **网络** | 安装更新和首次设置时可能需要互联网连接 | 提前确认安装环境网络可用 |

Windows 11 Home 和面向个人使用的 Pro 在首次设置时通常需要互联网连接和 Microsoft 账户；组织管理设备按管理员提供的账户与部署流程设置。

!!! tip "虚拟机先配置 UEFI 和虚拟 TPM"
    在 VMware Workstation 中创建虚拟机时选择 Windows 11 客户机类型，使用 UEFI 固件，并添加 **可信平台模块（vTPM）**。部分 VMware 版本需要先加密虚拟机，才能添加 vTPM。满足安装程序要求比绕过检查更适合长期使用；通用虚拟机创建流程见 [Ubuntu 22.04 部署教程](../linux/ubuntu-22.04.md)。

!!! warning "绕过硬件检查不等于获得支持"
    不建议在日常或生产设备上绕过 Windows 11 的最低硬件要求。安装程序允许继续，并不代表设备受微软支持、能够获得所有更新或适合承载重要数据。绕过方法仅适用于自担风险的测试环境；用于组织设备前先遵循组织的部署和合规要求。

### 安装介质准备

**物理机安装**：先备份重要文件，再使用微软官方工具或 [Rufus](https://rufus.ie/) 制作启动 U 盘。制作过程会清除 U 盘内容；启动前确认 UEFI 启动方式与设备固件设置匹配。

-   微软官方安装介质：适合在兼容设备上按默认要求安装。
-   Rufus：用于从 ISO 创建启动介质；可用选项随 Rufus 和 Windows ISO 版本变化，创建前仔细阅读提示。
-   [Ventoy](https://www.ventoy.net/cn/index.html)：适合在一个启动 U 盘中管理多个 ISO。

**虚拟机安装**：从微软官方来源获取 ISO，并将其挂载为虚拟光驱；安装前确认固件模式、虚拟 TPM、虚拟磁盘容量和启动顺序。

### 软件准备

| 软件 | 下载地址 |
| --- | --- |
| **Windows 11 ISO** | [微软官网](https://www.microsoft.com/software-download/windows11) |
| **Rufus**（推荐） | [rufus.ie](https://rufus.ie/) |

## 创建虚拟机（VMware Workstation）

VMware Workstation 创建虚拟机的通用步骤请参考 [Ubuntu 22.04 部署教程](../linux/ubuntu-22.04.md)。本文的规格是学习环境建议值，不是微软最低要求；如需理解宿主机、虚拟机和裸机的区别，可参考[裸金属、虚拟机与容器](../basics/baremetal-vm-container.md)。

### 客户机操作系统

```text
Microsoft Windows → Windows 11 x64
```

选择客户机操作系统 **Microsoft Windows → Windows 11 x64**，并在虚拟机固件选项中使用 **UEFI**。不同 Workstation 版本的菜单名称可能略有区别；重点是不要误选旧版 Windows 客户机或 Legacy BIOS。

### 虚拟机规格

```text
CPU：2 Core 以上
内存：8192 MB（8 GB，建议值）
磁盘：80 GB 或更大
网络：按需要选择 NAT 或桥接
```

网络模式按场景选择：NAT 适合一般上网和隔离测试；桥接让虚拟机作为局域网中的独立设备，便于从其他设备连接，但也会暴露在所在网络中。

!!! tip "添加 TPM 模块"
    关机后打开虚拟机设置 → **添加** → **可信平台模块（Trusted Platform Module）**。若 Workstation 提示需要加密虚拟机，先按软件提示配置加密，再添加 vTPM。完成后检查虚拟机固件为 UEFI；菜单细节可能因 Workstation 版本而异。

若当前 Workstation 版本不支持 vTPM，优先升级到支持该功能的版本或改用符合要求的设备；不要把跳过检查当成默认方案。

## 安装 Windows 11

### 启动安装介质

挂载 ISO → 开启虚拟机 → 在提示从 CD/DVD 启动时按任意键进入安装程序。如果没有出现启动提示，检查 ISO 是否已连接、是否勾选开机时连接，以及虚拟机启动顺序是否包含虚拟光驱。

---

### 语言和区域

选择安装语言、时间和货币格式、键盘或输入法 → **「下一步」** → **「现在安装」**。这些选项会影响初始区域格式和默认输入法，按实际使用地区选择。

---

### 测试环境中处理硬件兼容性检查（可选）

若安装程序提示设备不满足 Windows 11 要求，先记录具体原因，并优先返回虚拟机设置启用 UEFI、添加 vTPM，或在实体机固件中启用 TPM 2.0 和 Secure Boot。只有在隔离的测试环境中确需验证安装流程时，才考虑跳过兼容性检查。

#### 方法一：使用 Rufus 创建测试介质

使用 Rufus 写入 ISO 时，部分版本会显示用于调整安装要求的选项。只选择测试目的确实需要的选项，先阅读 Rufus 提示和影响说明；不要不加区分地勾选所有绕过项。具体选项取决于 Rufus 版本和所用 ISO。

#### 方法二：安装程序注册表选项（测试用途）

在安装界面按 `Shift + F10` 打开命令提示符，输入 `regedit`，定位到：

```text
HKEY_LOCAL_MACHINE\SYSTEM\Setup
```

右键 `Setup` → 新建 **项** → 命名为 `LabConfig`。仅当测试目的需要绕过对应检查时，在 `LabConfig` 中新建相应的 **DWORD (32 位)** 值并设为 `1`：

```text
BypassTPMCheck
BypassSecureBootCheck
```

关闭注册表和命令提示符，返回安装程序重试。安装程序版本不同，支持的检查项和行为可能变化；这些设置不是受支持的硬件升级方案，也不保证通过其他检查或后续更新。测试完成后不要将此镜像用于承载重要数据的设备。

---

### 选择安装版本

选择与你拥有的许可证相匹配的版本。若安装程序没有显示版本选择页，可能是 ISO 或产品密钥已预先确定版本；安装后可在“设置 → 系统 → 激活”核对当前版本和授权状态。

---

### 接受许可条款

勾选 **「我接受许可条款」** → **「下一步」**。

---

### 选择安装类型

在全新安装时选择 **「自定义：仅安装 Windows（高级）」**。如果是升级现有系统，不要误选此项；先确认已备份数据，并选择符合实际需求的升级或安装方式。

---

### 磁盘分区

选择目标磁盘和安装分区。**删除分区会清除该分区上的数据**；只有确认目标磁盘及其数据均可删除时，才删除旧分区并选择未分配空间继续。若磁盘内有需保留的数据，先停止操作并备份，不能仅凭磁盘顺序或容量猜测目标。

选择目标未分配空间后，Windows 安装程序会自动创建所需的系统分区。安装耗时受硬件、安装介质和更新情况影响。安装过程中系统会自动重启；首次重启后不要再次按键从 ISO 启动，否则可能重新进入安装程序。

## 初始设置

### 选择区域和键盘

按实际所在地区选择区域和键盘布局。中文环境可以选择“中国”和微软拼音；如需英文或其他布局，可在此添加，并按提示测试键盘布局。

---

### 网络连接

首次开机设置（OOBE）会按 Windows 版本、安装介质和设备用途显示网络与账户选项。Windows 11 Home 和面向个人使用的 Pro 通常需要联网并使用 Microsoft 账户完成设置；组织管理的设备应使用管理员提供的工作或学校账户及部署流程。

如需本地账户，先使用安装程序当前提供的受支持选项。网上流传的 `OOBE\BYPASSNRO` 等方法会随 Windows 构建版本变化，部分新版本可能不再提供或无法使用，不能视为通用步骤。对工作或学校设备，不要绕过组织账户和管理要求。

!!! tip "安装前准备账户与网络"
    提前确认虚拟机网卡已连接、能够访问网络，并准备好适用的 Microsoft 账户；组织环境则准备管理员分配的账户。若安装环境无法联网，先解决网络或介质问题，不要把旧版 OOBE 命令当作唯一恢复方案。

---

### 隐私设置

逐项阅读隐私设置说明，根据位置服务、诊断数据、查找设备和个性化体验等实际需求选择；不需要的可关闭。组织管理的设备应按单位策略设置，然后点击 **「接受」**。

---

### 自定义体验

根据用途选择是否启用备份、设备查找、试用服务或个性化建议等可选项；不确定时先了解选项影响，不必为了尽快进入桌面而一律跳过。

---

## 首次进入桌面

进入桌面后先确认开始菜单和任务栏正常显示，并检查“设置 → 系统 → 激活”中的版本和授权状态。随后完成设备驱动、网络与 Windows 更新检查，再开始安装日常应用。

---

## 安装后必做配置

### 安装 VMware Tools（虚拟机）

从 VMware Workstation 菜单选择 **「虚拟机」→「安装 VMware Tools」** 并按向导操作。安装后重启虚拟机，再检查分辨率、鼠标和网络驱动是否正常；剪贴板共享或拖放功能还可能需要在虚拟机设置中启用。

---

### 激活 Windows

```powershell
# 查看激活状态
slmgr /xpr
```

有正版密钥：设置 → 系统 → 激活 → 更改产品密钥。

核对已安装版本与许可证一致。`slmgr /xpr` 可查询激活到期状态，但不能替代 Windows 设置中的完整激活状态和许可证诊断。

---

### Windows 更新

设置 → Windows 更新 → 检查更新。安装适用的安全更新和驱动后按提示重启，再返回 Windows 更新检查是否还有待处理项目。重要设备更新前应确认备份和回滚方案。

### 安装结果检查

- **版本与激活**：在“设置 → 系统 → 激活”确认 Windows 版本和激活状态。
- **设备驱动**：打开设备管理器，检查是否有未知设备或黄色感叹号。
- **网络**：确认已获得预期 IP，并实际测试 DNS 解析和所需网络连接。
- **更新**：在 Windows 更新中检查并安装适用更新，按提示完成重启。

## 常见问题

### 虚拟机中 Windows 11 卡顿

1. 给日常桌面使用的虚拟机分配 8 GB 或更多内存，并确保宿主机有足够余量
2. 确认虚拟磁盘空间充足，再安装 VMware Tools 并重启客户机
3. 如仍卡顿，可在“设置 → 辅助功能 → 视觉效果”关闭不需要的透明效果和动画

---

### 提示「此电脑不符合 Windows 11 最低系统要求」

先记录提示指出的具体要求。虚拟机检查 UEFI 固件、vTPM 和客户机类型；实体机检查 UEFI、TPM 2.0 和 Secure Boot 设置。确认硬件兼容后再重试安装，不要先假定必须绕过。

---

### 安装完成后桌面没有「此电脑」图标

桌面右键 → 个性化 → 主题 → 桌面图标设置 → 勾选 **「计算机」**。

---

### 远程桌面连接不到这台电脑

Windows 11 Home 不能作为内置远程桌面服务的主机；如需从其他设备远程登录此电脑，应确认使用支持远程桌面主机功能的版本（例如 Pro），并检查远程桌面开关、防火墙和网络连通性。Windows 自带的远程桌面客户端与“允许其他设备连接到本机”是两项不同功能。

## 总结

Windows 11 的安装主线与 Windows 10 相似，但开始前应确认硬件、固件和许可证条件。本文的重点是：

1. **先检查兼容性**：确认处理器、TPM 2.0、UEFI/Secure Boot、内存和磁盘满足要求。
2. **虚拟机优先使用 vTPM**：配置 UEFI 和 vTPM，避免依赖不受支持的绕过方式。
3. **谨慎处理磁盘**：全新安装删除分区会清除数据，继续前确认目标磁盘并完成备份。
4. **按当前版本完成 OOBE**：网络和账户选项会随版本及用途变化，旧版离线账户命令并不保证可用。
5. **安装后做检查**：核对激活、驱动、网络和 Windows 更新。

对于不满足硬件要求的设备，优先升级硬件或继续使用受支持的系统版本；绕过检查仅用于自担风险的测试环境。 🚀
